# T010 pool thermostat

Made by UAB "Optika ir technologija" in Lithuania, sold through
[baseinai.lt](https://baseinai.lt/). The device's start-up screen reads
"THERMOSTAT T010" and "O&Technologija".

Tested with **firmware 1.7**, connected through a Modbus TCP-to-RS-485
gateway. The register map below comes from the device firmware and was checked
against the device.

## Communication

- Modbus RTU, 38400 8N1, fixed in the firmware.
- Modbus ID 1–32, factory default 1, set in the device menu.
- Holding registers 40001–40009, sent as addresses 0–8 (address = register −
  40001).
- Function 03 reads up to 10 registers per request. The library reads all 9
  registers, 40001–40009, in one request.
- Function 06 writes the settings 40006–40009, one register per request. No
  other function codes.
- Exceptions: 1 unsupported function, 2 bad address or register count, 3 value
  out of range.

## Register map

| Register | Address | Read/write | Content |
|---|---|---|---|
| 40001 | 0 | R | High byte: instrument type, `0x15` for a T010. Low byte: software version × 10 (17 = 1.7) |
| 40002 | 1 | R | Water temperature × 10 (°C), offset already applied |
| 40003 | 2 | R | Heating power, % (low byte) |
| 40004 | 3 | R | Heating delay still to run: minutes (high byte), seconds (low byte) |
| 40006 | 5 | R/W | Setpoint × 10 (°C), 50–400. Anything else returns exception 3 |
| 40007 | 6 | R/W | Temperature offset × 10 (°C), signed, −31 to +31 (high byte 0xFF when negative) |
| 40008 | 7 | R/W | Heating delay setting, minutes, 0–59. More returns exception 3 |
| 40009 | 8 | R/W | Flags, below |

Register 40009 (address 8):

| Bit | Read/write | Meaning |
|---|---|---|
| 0 | R | The display is not on its main screen: menu, alarm or delay countdown |
| 1 | R | Sensor disconnected: raw temperature below 3.1 °C |
| 2 | R | Sensor supply below 6.0 V for about 2 s (masks bit 1) |
| 3 | R | EEPROM error; firmware 1.7 never sets it |
| 8 | R/W | Heating blocked |
| 9 | R/W | Delaying: the heating delay is counting down |

## Writing

- **40006 setpoint** and **40008 delay** are checked by the firmware; a value
  out of range returns exception 3 and changes nothing.
- **40007 offset**: the firmware uses only the low byte, keeping its sign and
  low five bits, so a value outside ±3.1 °C would wrap. The device's own menu
  limits it to ±3.1 °C.
- **40009 flags**: a write only changes bits 8 and 9; the other bits are status
  and ignored.
- The firmware stores every write in EEPROM, also when the value is
  unchanged.
- Writes take effect while the device menu is open too.

The library checks each value against these ranges before sending it, never
sends a value the device already holds, and reads the device just before it
compares, so a change made on the device itself is not overwritten from an old
reading. Register 40009 is read back and merged, so changing one flag keeps the
other. After each write the library reads the device until it shows the new
value (up to 5 s); behind a gateway that caches reads, that takes about 1 s.

## Behaviour

- **Heating power.** In relay mode the output is 0 or 100 %. In PWM mode it is
  100 % when the setpoint is 0.5 °C or more above the water temperature, and
  20, 40, 60 or 80 % for a gap of 0.1–0.4 °C.
- **Relay control.** On when the temperature is 0.2 °C below the setpoint, off
  5 s after reaching it.
- **Heating is off** while it is blocked, while the delay runs, and while any
  alarm bit is set.
- **The delay** counts down the minutes in 40008 at every power-up, after an
  alarm clears, and when bit 9 is written as 1. A key press on the device, a
  delay setting of 0, or writing bit 9 as 0 cancels it. Opening the setpoint
  menu on the device cancels it too.
- **Near-freezing water reads as a sensor fault**, since a raw temperature
  below 3.1 °C (before the offset) sets bit 1. A sensor supply below 6.0 V for
  about 2 s sets bit 2 and clears bit 1.
- **On the device**, the setpoint changes in 0.5 °C steps and cannot be changed
  while heating is blocked; a long press of plus or minus in the setpoint menu
  allows or blocks heating. Over Modbus the setpoint takes 0.1 °C steps at any
  time.

## In Home Assistant

| Entity | Type | Register |
|---|---|---|
| Pool Thermostat | Climate: heat/off, target and current temperature, heating/idle/off | 40002, 40003, 40006, 40009 bit 8 |
| Pool Heating | Switch: on unless heating is blocked | 40009 bit 8 |
| Pool Delaying | Switch | 40009 bit 9 |
| Set Temperature | Number, 5.0–40.0 °C in 0.1 °C steps | 40006 |
| Offset Temperature | Number, −3.1 to +3.1 °C | 40007 |
| Set Delay Time | Number, 0–59 min | 40008 |
| Pool Temperature, Heating Mode, Heating Power, Delay Time | Sensors | 40002–40004 |
| Menu Mode, Thermometer Alarm, Short Connection Alarm, EEPROM Alarm | Binary sensors | 40009 bits 0–3 |
| Thermostat Firmware | Diagnostic sensor | 40001 |

The thermostat is in heat mode unless heating is blocked, and heating whenever
the heating power is above 0 %. Its target temperature moves in 0.5 °C steps,
like the device's keypad; Set Temperature allows 0.1 °C. Turning Pool Delaying
on starts a new countdown and blocks heating until it ends.
