# T010 pool thermostat

Pool heating thermostat T010 by Optika ir technologija, firmware 1.7. In the
integration "Pool equipment" (domain `pool_modbus`, version 2026.10.0) it is
the device type **T010 pool thermostat**; a new device is offered the name
"Thermostat" and Modbus ID 1, the firmware's factory default.

## Communication

- Modbus RTU, 38400 8N1, on a serial port or through a Modbus TCP connection
  (for example a Modbus TCP-to-RS-485 gateway).
- Holding registers 40001–40010, sent as wire addresses 0–9 (address =
  register − 40001).
- Function 03 reads. The firmware answers at most 10 registers per request.
  The integration reads addresses 0–8 (40001–40009); each scan group reads the
  registers it needs in one request within that range, at most 9 registers.
- Function 06 writes one register per request, addresses 5–8 (40006–40009).
  No other function codes are used.
- When a device is added, the integration reads it and accepts it only if the
  high byte of 40001 is `0x15` (T010).

## Register map

| Register | Address | Read/write | Content |
|---|---|---|---|
| 40001 | 0 | R | High byte: instrument type, `0x15` for a T010. Low byte: software version × 10 (17 = 1.7) |
| 40002 | 1 | R | Water temperature × 0.1 °C, offset already applied |
| 40003 | 2 | R | Heating power, %: 0 or 100 in relay mode, steps of 20 in PWM mode |
| 40004 | 3 | R | Heating delay still to run: minutes (high byte), seconds (low byte) |
| 40005 | 4 | R | Always 0 |
| 40006 | 5 | R/W | Setpoint × 0.1 °C, 5.0–40.0 °C |
| 40007 | 6 | R/W | Temperature offset × 0.1 °C, signed (two's complement), −3.1 to +3.1 °C |
| 40008 | 7 | R/W | Heating delay setting, minutes, 0–59 |
| 40009 | 8 | R/W | Flags, below |
| 40010 | 9 | | Free register, not part of the thermostat's data |

Register 40009 (address 8):

| Bit | Read/write | Meaning |
|---|---|---|
| 0 | R | The display is not on its main screen (menu, alarm or delay countdown) |
| 1 | R | Sensor disconnected: raw temperature below 3.1 °C |
| 2 | R | Sensor supply below 6.0 V for about 2 s |
| 3 | R | EEPROM error |
| 8 | R/W | Heating blocked |
| 9 | R/W | Delaying: the heating delay is counting down |

## Entities

Entity ids are `<platform>.pool_thermostat_<name>`; the climate entity is the
device's main entity and has no name of its own, so its id is
`climate.pool_thermostat`. A device with the entity id prefix `<prefix>` gets
`climate.pool_thermostat_<prefix>` and `<platform>.pool_thermostat_<prefix>_<name>`.
Read groups: fast every 5 s, slow every 15 s by default (set per device in
Configure). Section: Controls and Sensors have no entity category;
Configuration and Diagnostic are Home Assistant's entity categories. Every
entity is enabled by default. The T010 has no optional parts.

| Entity | Entity id | Platform | Register / bit | Values | Read | Section |
|---|---|---|---|---|---|---|
| Thermostat (the device's name) | `climate.pool_thermostat` | Climate | 40002, 40003, 40006, 40009 bit 8 | Below | Fast | Controls |
| Heating Delay | `switch.pool_thermostat_heating_delay` | Switch (`switch`) | 40009 bit 9 | on / off | Fast | Controls |
| Delay Remaining | `sensor.pool_thermostat_delay_remaining` | Sensor | 40004 | mm:ss | Fast | Sensors |
| Sensor Alarm | `binary_sensor.pool_thermostat_sensor_alarm` | Binary sensor (`problem`) | 40009 bit 1 | on / off | Fast | Sensors |
| Sensor Supply Alarm | `binary_sensor.pool_thermostat_sensor_supply_alarm` | Binary sensor (`problem`) | 40009 bit 2 | on / off | Fast | Sensors |
| EEPROM Alarm | `binary_sensor.pool_thermostat_eeprom_alarm` | Binary sensor (`problem`) | 40009 bit 3 | on / off | Fast | Sensors |
| Temperature Offset | `number.pool_thermostat_temperature_offset` | Number, input box (`temperature_delta`) | 40007, × 0.1 | −3.1 to +3.1 °C, step 0.1 | Slow | Configuration |
| Delay Setting | `number.pool_thermostat_delay_setting` | Number, input box (`duration`) | 40008 | 0–59 min, step 1 | Slow | Configuration |
| Menu Mode | `binary_sensor.pool_thermostat_menu_mode` | Binary sensor | 40009 bit 0 | on / off | Slow | Diagnostic |
| Firmware | `sensor.pool_thermostat_firmware` | Sensor | 40001 low byte | e.g. 1.7 | Slow | Diagnostic |

The firmware version is also shown as the device's software version.

### Climate entity

The climate entity holds the water temperature, heating on/off, the setpoint,
the heating action and the heating power:

- **Current temperature:** 40002 × 0.1 °C, in tenths.
- **Target temperature:** 40006 × 0.1 °C, 5.0–40.0 °C. The entity steps in
  0.5 °C; a value is written in the thermostat's 0.1 °C resolution.
- **HVAC modes:** heat and off. Heat while 40009 bit 8 (heating blocked) is
  clear, off while it is set. Turn on and turn off set heat and off.
- **HVAC action:** off while heating is blocked, else heating while the heating
  power is above 0 %, else idle.
- **Attribute `heating_power`:** 40003, in %.

### Heating Delay

Heating Delay shows 40009 bit 9. Turning it on writes bit 9 as 1, which starts
the thermostat's delay countdown; turning it off writes it as 0. Delay
Remaining shows the time still to run from 40004, Delay Setting the length of
the delay in 40008.

### Alarms

Sensor Alarm (bit 1), Sensor Supply Alarm (bit 2) and EEPROM Alarm (bit 3) are
problem binary sensors from 40009. Menu Mode (bit 0) shows that the display is
not on its main screen.

## Writing

- The firmware stores every write to 40006–40009 in its EEPROM, also when the
  value is unchanged. The integration therefore reads the device just before
  each write and does not write a value the thermostat already holds, so a
  change made on the keypad is compared against a fresh reading.
- Setpoint (40006), offset (40007) and delay setting (40008) are checked
  against the ranges above before any request; a value outside them is
  refused. Setpoint and offset are rounded to 0.1 °C, the delay must be a
  whole number of minutes. A negative offset is written as a signed 16-bit
  value.
- The flags register 40009 is written as a whole word computed from the last
  read, so changing bit 8 (heat/off) or bit 9 (Heating Delay) keeps the other
  bits.
- Each write is confirmed by reading the device until it shows the new value
  (up to 5 s). The read before a write is retried once after 0.5 s if it gets
  no answer.
- Writes to one device run one at a time. After a write the integration reads
  every scan group, so all entities show the result.

## Not included

- 40005 (always 0) and 40010 (free register) are not read.
- The instrument type (40001 high byte) is used only to recognise the device
  when it is added; it has no entity.
